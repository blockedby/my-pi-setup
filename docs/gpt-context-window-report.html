Three layers produce one number

The footer does not invent the context size. It reads the active model metadata after built-in data and user overrides have been composed.

Layer 1 / shipped data

Built-in catalog

Pi 0.82.1 ships GPT-5.6 Sol, Terra, and Luna as 272K context and 128K maximum output.

→
Layer 2 / your control

Pipi models.json

A matching modelOverrides entry replaces contextWindow while preserving the model's other metadata.

→
Layer 3 / runtime

Session behavior

The resulting value drives the footer gauge, output-token clamping, overflow checks, and automatic compaction threshold.

Do not edit the model store or installed package data. ~/.pipi/agent/models-store.json is generated catalog state, and files under ~/.local/lib/node_modules/… are replaced by updates. Use models.json as the durable override layer.
3

“Maximum” has two meanings

Limit What was discovered What to set
Pi configuration contextWindow is parsed as a JSON number. The implementation has no model-capability upper-bound check. A temporary configuration test confirmed that a 1,050,000 override is composed for openai-codex/gpt-5.6-sol and displayed as 1.1M. Do not treat parser acceptance as model support.
GPT-5.6 capability OpenAI documents a 1,050,000-token context window and a separate 128,000-token maximum output for Sol, Terra, and Luna. 1,050,000 context; leave output at 128,000.
Current Pipi default Pi ships 272,000 context for all three GPT-5.6 models. This Pipi profile now overrides Sol to 350,000 and Terra/Luna to 300,000. Pi's documentation says the shorter built-in default keeps requests in OpenAI's short-context pricing tier. Use the configured 350K / 300K / 300K values.
The 272K boundary is economic, not the GPT-5.6 architecture limit. OpenAI says requests above 272K input tokens are billed at 2× input and 1.5× output rates for the full request. Raising Pi's metadata does not reserve tokens or force the upstream service to accept them.
4

The configuration to use

Choose the provider block that matches how the model is authenticated. This Pipi session uses the ChatGPT/Codex provider, while Pi's documented long-context example targets direct OpenAI API access.

Current Pipi provider: openai-codex

{
  "providers": {
    "openai-codex": {
      "modelOverrides": {
        "gpt-5.6-sol": {
          "contextWindow": 1050000
        }
      }
    }
  }
}

This override is proven to change Pi's local model metadata. However, the installed Pi documentation only explicitly promises the 1.05M opt-in for direct OpenAI. A ChatGPT/Codex subscription backend may enforce its own limit. If it does, Pi will eventually receive an overflow instead of gaining extra upstream capacity.

Documented route: direct OpenAI API

{
  "providers": {
    "openai": {
      "modelOverrides": {
        "gpt-5.6-sol": {
          "contextWindow": 1050000
        }
      }
    }
  }
}

Add equivalent entries for gpt-5.6-terra and gpt-5.6-luna only if those models are used. There is no reason to override maxTokens: the built-in value already matches OpenAI's 128K maximum output.

5

What changes after the override

  1. Pi waits longer to compact. Automatic compaction triggers when estimated context exceeds contextWindow − reserveTokens. An inflated value can therefore cause avoidable upstream overflow errors.
  2. The footer reports the larger capacity. Context percentage is calculated against the composed model value, so 1,050,000 appears as approximately 1.1M in --list-models.
  3. Pricing metadata survives. A modelOverrides change to context alone preserves the built-in long-context pricing tier. Requests above 272K input use that tier for usage estimates.

Apply and verify

The smallest safe workflow is to create the override, reload model data, and inspect the composed result. 

# 1. Create or edit the Pipi-specific file
$EDITOR /home/kcnc/.pipi/agent/models.json

# 2. In Pipi, open /model so models.json is reloaded,
#    then reselect gpt-5.6-sol if needed.

# 3. Verify from the shell
pipi --list-models | grep 'gpt-5.6-sol'

Expected local result after the 1.05M override: the context column reads 1.1M and the max-output column remains 128K. If real requests fail before that size, lower the override to the limit actually supported by the selected provider.
